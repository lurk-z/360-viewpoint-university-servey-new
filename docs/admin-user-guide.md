# คู่มือผู้ดูแลและผู้พัฒนา Virtual Tour

คู่มือนี้ใช้เนื้อหาเดียวกับหน้า `/admin/help` อธิบายทั้งงานที่ทำผ่าน Admin และงาน Navigation/Fallback ที่ต้องแก้ใน VS Code โดยแยกขอบเขตให้ชัดเจน

## คำสำคัญก่อนเริ่ม

- **ฉบับร่าง (Draft)** คือข้อมูลที่ผู้ดูแลกำลังแก้ ผู้ชมยังไม่เห็น
- **เผยแพร่แล้ว (Published)** คือข้อมูลที่หน้า Tour และ AI ใช้งานจริง
- **เก็บเข้าคลัง (Archive)** คือซ่อนรายการโดยไม่ลบถาวรและยังนำกลับมาแก้ได้
- **ปุ่ม Info** คือปุ่มวงกลม `i` บนภาพ 360 ตำแหน่งปุ่มอยู่ใน “โครงสร้างทัวร์” แต่ข้อความและรูปอยู่ใน “สถานที่สำคัญ”
- **ลูกศรนำทาง** คือปุ่มเดินไปยังฉากอื่น แก้ใน VS Code เท่านั้น ไม่แก้ในหน้า Admin

## สิทธิ์ Admin และ Editor

- `Editor` เพิ่มและแก้ฉบับร่าง อัปโหลดรูป และดูตัวอย่างได้
- `Admin` ทำได้เหมือน Editor และเผยแพร่ ยกเลิกเผยแพร่ เก็บเข้าคลัง ลบ จัดการผู้ใช้ สำรองข้อมูล และเผยแพร่โครงสร้างทัวร์ได้

## เพิ่มปุ่ม Info ใหม่

ปุ่ม Info หนึ่งจุดมีสองส่วนที่ต้องเผยแพร่แยกกัน ได้แก่ **ตำแหน่งปุ่ม** และ **เนื้อหา**

1. เปิด `/admin/tour` หรือเลือกเมนู **โครงสร้างทัวร์**
2. เลือกฉากที่ต้องการจากรายการด้านซ้าย
3. หมุนภาพ 360 ให้ตำแหน่งที่ต้องการอยู่กลางภาพ
4. ในส่วน **ปุ่ม Info** คลิกตำแหน่งบนภาพ 360 เพื่อวางปุ่ม
5. ตรวจ `Hotspot ID` ซึ่งระบบสร้างให้ และปรับ `yaw`/`pitch` ของ Info ได้หากจำเป็น
6. กด **บันทึกฉบับร่าง** ระบบจะสร้างรายการรอกรอกในหน้า “สถานที่สำคัญ” ให้อัตโนมัติ
7. เปิด `/admin/places` ค้นหาด้วยชื่อฉากหรือ Hotspot ID แล้วเปิดรายการนั้น
8. กรอกชื่อและรายละเอียดภาษาไทย–อังกฤษ เพิ่มรูปอย่างน้อยหนึ่งรูป และใส่ชื่อแหล่งข้อมูล
9. กด **บันทึกฉบับร่าง** แล้วเปิดตัวอย่างเพื่อตรวจข้อความและรูป
10. ให้ Admin กด **เผยแพร่** หรือ **อัปเดตข้อมูลที่เผยแพร่** ในรายการสถานที่สำคัญ
11. กลับไป `/admin/tour` แล้วให้ Admin กด **เผยแพร่โครงสร้างทัวร์**
12. กด **ดูหน้าเว็บจริง** ของฉากนั้น แล้วทดสอบปุ่ม Info ทั้งเมาส์และมือถือ

ถ้าปุ่มขึ้นแต่หน้าต่างไม่มีข้อมูล ให้ตรวจว่ารายการสถานที่สำคัญของ Hotspot ID เดียวกันเผยแพร่แล้ว ถ้ามีข้อมูลแต่ปุ่มไม่ขึ้น ให้ตรวจว่าโครงสร้างทัวร์ถูกเผยแพร่แล้ว

### สถานะ Info ที่ควรรู้

| สถานะ | ความหมาย | สิ่งที่ต้องทำ |
| --- | --- | --- |
| ยังไม่บันทึก | ตำแหน่งเปลี่ยนเฉพาะใน Browser | กดบันทึกฉบับร่าง |
| บันทึกฉบับร่างแล้ว | Draft มีตำแหน่งนี้แล้ว แต่ Public อาจยังไม่มี | เปิด Draft Preview |
| เผยแพร่โครงสร้างแล้ว | Public Tour มีปุ่ม Info แล้ว | ตรวจเนื้อหาในสถานที่สำคัญ |
| เนื้อหาสถานที่เผยแพร่แล้ว | ชื่อ รายละเอียด รูป และอ้างอิงพร้อมให้ผู้ชมเปิด | ตรวจหน้าเว็บจริง |

## ย้ายหรือลบปุ่ม Info

- เปิดฉากใน `/admin/tour` เลือก Info แล้วคลิกตำแหน่งใหม่หรือแก้ `yaw`/`pitch`
- กด **บันทึกฉบับร่าง** และ **เผยแพร่โครงสร้างทัวร์** ทุกครั้งที่ต้องการให้หน้าเว็บจริงเปลี่ยน
- การลบ Info ออกจากฉากจะลบเฉพาะตำแหน่งปุ่มเมื่อเผยแพร่โครงสร้าง เนื้อหาเดิมใน “สถานที่สำคัญ” ไม่ควรถูกลบถาวรโดยไม่ตรวจสอบ ให้เก็บเข้าคลังหากไม่ใช้งานแล้ว
- ห้ามเพิ่มหรือย้าย Info ใน `src/tour-data.ts` เป็นวิธีหลัก เพราะไฟล์นั้นเป็นข้อมูลสำรองฉุกเฉิน ข้อมูลจริงเมื่อระบบพร้อมมาจาก Admin/Supabase

## แก้ข้อมูลคณะ หลักสูตร กิจกรรม และสถานที่สำคัญ

1. เปิดหมวดข้อมูลที่ต้องการ
2. กดเพิ่มรายการใหม่ หรือเปิดรายการเดิม
3. กรอกตามขั้น **ข้อมูลทั่วไป → ไทย → อังกฤษ → รูป/อ้างอิง → ตรวจและเผยแพร่**
4. หลักสูตรต้องตรวจระดับการศึกษา วุฒิที่รับสมัคร ความสนใจ และแนวทางอาชีพ เพราะ AI ใช้ข้อมูลเหล่านี้จัดอันดับคำแนะนำ
5. กิจกรรมควรใส่ช่วงวันที่และ Scene ID ที่เกี่ยวข้อง ส่วน Info ต้องใช้ Scene ID/Hotspot ID เดียวกับโครงสร้างทัวร์
6. กดบันทึกฉบับร่างก่อนเสมอ การบันทึกนี้ยังไม่เปลี่ยนหน้าเว็บจริง
7. ตรวจตัวอย่าง แล้วให้ Admin เผยแพร่หรืออัปเดตข้อมูลที่เผยแพร่
8. ใช้ “เก็บเข้าคลัง” เมื่อต้องการซ่อนรายการและยังเผื่อกู้คืน ไม่ควรลบถาวรถ้าไม่จำเป็น

AI ใช้เฉพาะข้อมูลที่เผยแพร่แล้ว การแก้ฉบับร่างจึงไม่เปลี่ยนคำตอบของ AI จนกว่าจะเผยแพร่

## เพิ่มฉาก Panorama ใหม่

1. เปิด `/admin/tour` แล้วกด **เพิ่มฉาก** หรือรัน `npm run tour:add-scene` เพื่อสร้าง Scene JSON แล้วกด **นำเข้า Scene JSON**
2. ตั้ง Scene ID ภาษาอังกฤษที่ไม่ซ้ำ และอัปโหลด JPEG/WebP อัตราส่วน 2:1 ไปยังคลัง Panorama
3. กรอกชื่อและคำอธิบายไทย–อังกฤษ ตั้ง Panorama URL, `yaw`, `pitch`, `zoom` และคลิกพิกัดบนแผนที่
4. บันทึกฉบับร่าง แล้วกด **ดูฉบับร่าง** ของฉากนั้นเพื่อตรวจภาพ มุมเริ่มต้น การ์ดฉาก และตำแหน่งแผนที่
5. เพิ่มบล็อก Fallback และลูกศรไป–กลับใน `src/tour-data.ts` โดยใช้ Scene ID เดียวกัน จากนั้นตรวจใน Development
6. รัน `npm run sync:arrows` เมื่อเส้นทางสมบูรณ์ แล้ว Admin จึงเผยแพร่โครงสร้างทัวร์

อย่าเผยแพร่ฉากที่ยังไม่มีเส้นทางเข้า–ออก และอย่าใช้ `npm run sync:tour` กับงานเพิ่มฉากทั่วไป เพราะคำสั่งนี้มีไว้สำหรับชุดอัปเดตโครงสร้างที่เขียนไว้เฉพาะเท่านั้น

## คู่มือ VS Code

งานข้อมูลทั่วไปและตำแหน่ง Info ทำใน Admin ก่อน ส่วน VS Code ใช้กับ Navigation, Emergency Fallback, สื่อประกอบ และส่วนติดต่อที่ไม่มีแบบฟอร์มใน Admin

### เปิดโปรเจกต์และตรวจ Fast Refresh

เปิด Terminal ในโฟลเดอร์โปรเจกต์แล้วรัน:

```powershell
npm install
npm run dev
```

เปิด `http://localhost:3000` เมื่อแก้และบันทึกไฟล์ให้ตรวจว่า Fast Refresh แสดงผลโดยไม่ต้องปิด Server เมื่อทำงานเสร็จให้รัน `npm run check` ก่อนส่งมอบ

### หน้าที่ของไฟล์หลัก

| ไฟล์ | ใช้แก้อะไร |
| --- | --- |
| `src/tour-data.ts` | บล็อกฉากสำรองและลูกศร Navigation: `id`, `target`, `yaw`, `pitch`, `direction` |
| `src/tour-supplemental-media.ts` | Panorama ตัวอย่างและผังอาคารที่เปิดจากเมนูสื่อ ไม่ใช่ฉากเดิน |
| `src/tour-scene-titles.ts` | รายการ Migration ชื่อฉากเก่าเท่านั้น ฉากใหม่ที่ตั้งชื่อถูกต้องไม่ต้องเพิ่ม |
| `src/i18n.ts` | ข้อความภาษาไทย–อังกฤษของ Public UI |
| `src/styles.css` | รูปแบบหน้า Public Tour และ Viewer |
| `app/admin/admin.css` | รูปแบบหน้า Admin รวมหน้าคู่มือ |
| `public/mainimages/` | Panorama และสื่อเดิมที่เก็บกับโปรเจกต์ |
| `.env.local` | ค่าเชื่อมต่อ Supabase/Gemini ห้าม Commit หรือส่งให้ผู้อื่น |

ฉากใหม่ไม่ต้องเพิ่มใน `src/tour-scene-titles.ts` ให้ตั้งชื่อสุดท้ายใน Admin และในบล็อกฉากโดยตรง ไฟล์นี้มีไว้ย้ายชื่อฉากเก่าที่เคยมีคำว่า “จุดที่/Point” เท่านั้น

## แก้ลูกศรนำทาง

ส่วนนี้ต้องใช้ VS Code เพราะหน้า Admin แสดงลูกศรแบบอ่านอย่างเดียว

ลูกศรอยู่ใน `hotspots` ของฉากต้นทางใน `src/tour-data.ts` และต้องมี ID ไม่ซ้ำ ส่วน `target` ต้องตรงกับ Scene ID ที่มีอยู่จริง ตัวอย่าง:

```ts
{ id: 'scene-a-to-scene-b', type: 'scene', target: 'sceneB', yaw: 90.0, pitch: -8.0, direction: 'up' }
```

- ไม่ใส่ `direction` หรือใช้ `standard` สำหรับทางราบ
- ใช้ `up` สำหรับขึ้นชั้น และ `down` สำหรับลงชั้น

วิธีจัดตำแหน่ง:

1. รัน `npm run dev` และเปิดฉากต้นทางที่ต้องการ
2. เปิด **จัดตำแหน่งลูกศร** จากแถบเครื่องมือด้านขวา มือถือเปิดจากเมนูเครื่องมือ
3. เลือก Hotspot แล้วคลิก Panorama เพื่อ Preview ตำแหน่งใหม่
4. กด **คัดลอก object** แล้ววางแทน object เดิมในฉากต้นทางของ `src/tour-data.ts`
5. กด **คืนค่าจากโค้ด** หากต้องการยกเลิก Preview เครื่องมือนี้ไม่เขียนไฟล์หรือ Supabase ให้อัตโนมัติ
6. เพิ่มลูกศรย้อนกลับในฉากปลายทางและตรวจ `target` ทั้งสองทิศทาง
7. บันทึกไฟล์ ตรวจ Fast Refresh และทดสอบเดินไป–กลับ
8. สำรองข้อมูลแล้วรัน `npm run sync:arrows` เพื่อนำเฉพาะ Navigation ไปยัง Draft และ Published
9. รันคำสั่งซ้ำหลังสำเร็จ ค่า `added/updated/moved/deleted` ควรเป็น `0`

`npm run sync:arrows` ซิงก์เฉพาะ Navigation ไม่สร้างฉากหรือรายละเอียด Info ถ้าคำสั่งแจ้ง Conflict, Target หาย หรือเส้นทางขาดลูกศรย้อนกลับ ให้หยุดและแก้ข้อมูลก่อน ห้ามฝืนเขียนทับ และอย่าแก้ Navigation พร้อมกันหลายเครื่อง

## สื่อประกอบภายในอาคาร

Panorama ห้องตัวอย่างและผังอาคารเป็น “สื่อประกอบ” ไม่ใช่ฉากเดิน จึงไม่แสดงบนแผนที่ Text Tour หรือเส้นทาง AI

1. เพิ่มไฟล์รูปใน `public/mainimages/` หรือใช้ URL สื่อที่ระบบเข้าถึงได้
2. เพิ่มรายการแบบ Typed ใน `src/tour-supplemental-media.ts` โดยเลือกชนิด `panorama` หรือ `floor-plan`
3. เชื่อมกลุ่มสื่อกับ Scene ID ใน `getTourSupplementalMediaGroups()`
4. ทดสอบเปิด ปิด สลับรายการ และตรวจว่าฉากหลัก มุมกล้อง และ Zoom ไม่เปลี่ยน

สำหรับฉาก Fallback ให้สร้างและบันทึกฉากใน Admin ก่อน จากนั้นเพิ่ม Panorama ใน `tourMedia` (เมื่อใช้ไฟล์ใน `public/mainimages/`) และเพิ่มบล็อกฉากเต็มใน `src/tour-data.ts` ด้วย Scene ID เดียวกัน พร้อมลูกศรไป–กลับ

Info เพิ่ม ย้าย และลบจาก Visual Tour Editor ส่วนข้อความ Info แก้ใน “สถานที่สำคัญ” ข้อมูล Info ในโค้ดเป็น Emergency Fallback ไม่ใช่แหล่งแก้หลัก

## Media และข้อมูลที่ AI ใช้

- เมนู Media ใช้กับรูปคณะ หลักสูตร กิจกรรม และสถานที่สำคัญ ส่วน Panorama ของฉากอัปโหลดใน Visual Tour Editor
- ก่อนลบรูปให้ตรวจจำนวนรายการที่ใช้งานอยู่ ไม่ควรลบรูปที่ยังถูกอ้างอิง
- AI ใช้ข้อมูล Published เท่านั้น โดยเฉพาะชื่อคณะ หลักสูตร ระดับ วุฒิ ความสนใจ แนวทางอาชีพ กิจกรรม และสถานที่
- ถ้าคำตอบ AI ไม่เปลี่ยนหลังบันทึก ให้ตรวจว่าเผยแพร่รายการแล้ว ไม่ใช่เพียงบันทึก Draft

## ตรวจฉบับร่างและหน้าเว็บจริง

- **Draft Preview** ใช้ตรวจสิ่งที่บันทึกเป็นฉบับร่าง ยังไม่ใช่สิ่งที่ผู้ชมเห็น
- **ดูหน้าเว็บจริง** ใช้ตรวจ Published เท่านั้น
- หลังเผยแพร่ อุปกรณ์เดิมจะรับข้อมูลใหม่อัตโนมัติ หากยังเห็นข้อมูลเก่าให้รอรอบอัปเดตสั้น ๆ แล้วกด `Ctrl+F5`; มือถือให้ปิดแท็บเดิมและเปิด URL ใหม่
- การ์ดข้อมูลฉากมาจาก Visual Tour Editor ส่วนหน้าต่างปุ่ม Info มาจาก “สถานที่สำคัญ” ทั้งสองส่วนเป็นข้อมูลคนละชุด

## ประวัติ สำรอง และกู้คืน

- ก่อนแก้ข้อมูลจำนวนมากหรือรันคำสั่งซิงก์ ให้เปิด `/admin/backup` แล้วดาวน์โหลด JSON เก็บไว้
- JSON ใช้สำรองและกู้ระบบ ส่วน CSV ใช้สำหรับอ่านหรือทำรายงาน ไม่ใช่ไฟล์กู้ระบบ
- การนำเข้า JSON มีขั้น Preview ก่อน Commit จะสร้างเป็นฉบับร่างและข้ามรายการที่ ID/Slug ชน ไม่เขียนทับอัตโนมัติ
- การกู้ Revision จะสร้างฉบับร่างก่อน ไม่เผยแพร่ทันที ควรตรวจตัวอย่างก่อนเผยแพร่ทุกครั้ง
- เมนูประวัติระบบใช้ตรวจว่าใครทำงานชนิดใดกับรายการใด โดยไม่เก็บข้อความสนทนา Token หรือ Secret
- หากปิดหน้าระหว่างกรอก ฟอร์มสามารถเสนอข้อมูลกู้คืนจาก Browser ได้ภายในช่วงเวลาที่ระบบกำหนด

## Migration และสถานะระบบ

เมื่อหน้า `/admin/system` แจ้ง “รอรัน Migration”:

1. กดปุ่มคัดลอก Migration ที่ขาด
2. เปิด Supabase → SQL Editor → New query
3. วาง **ข้อความ SQL ที่ขึ้นต้นด้วย `create table`, `alter table` หรือคำสั่ง SQL อื่น** ไม่ใช่คำสั่ง PowerShell
4. กด Run แล้วกลับมากด “ตรวจสอบอีกครั้ง”

Environment Secret แก้จากไฟล์ `.env.local` เท่านั้น หน้า Admin จะแสดงเพียงสถานะและจะไม่แสดง Secret

## เปิดและปิดโปรเจกต์บน Windows

- วิธีง่าย: ดับเบิลคลิก `start-tour.bat` เพื่อเปิด และ `stop-tour.bat` เพื่อปิด
- จาก Terminal: ใช้ `npm run dev` และปิดด้วย `Ctrl+C`
- หากขึ้น `EADDRINUSE` แปลว่ามี Server ใช้พอร์ต 3000 อยู่แล้ว ให้ใช้เว็บที่เปิดอยู่หรือหา PID ด้วย `netstat -ano | findstr :3000` แล้วหยุดเฉพาะ PID ฝั่ง `LISTENING` ด้วย `taskkill /PID <PID> /T /F`
- มือถือและคอมพิวเตอร์ต้องอยู่ Wi-Fi เดียวกัน มือถือเปิด `http://<IPv4-ของคอมพิวเตอร์>:3000`

## ตรวจเมื่อ Info ไม่แสดง

ตรวจตามลำดับนี้:

1. ฉากและ Info ถูกบันทึกเป็นฉบับร่างแล้วหรือยัง
2. รายการใน “สถานที่สำคัญ” ใช้ Hotspot ID และ Scene ID ตรงกับปุ่มหรือไม่
3. เนื้อหาสถานที่สำคัญเผยแพร่แล้วหรือยัง
4. โครงสร้างทัวร์เผยแพร่แล้วหรือยัง
5. รายการไม่ได้ถูกเก็บเข้าคลัง
6. เปิด Public Tour ไม่ใช่ Draft Preview และรีเฟรชข้อมูลล่าสุดแล้ว

หากยังไม่พบ ให้เปิด `/admin/system` เพื่อตรวจ Supabase, Migration และโครงสร้างทัวร์ก่อนแก้โค้ด

## แก้ Login, Supabase และข้อมูลเก่าจาก Service Worker

- ถ้า Login ขึ้น `fetch failed` ให้ตรวจอินเทอร์เน็ต, Supabase URL/Key และ `.env.local` ก่อนสรุปว่ารหัสผ่านผิด
- ถ้าขึ้น “รอรัน Migration” ให้รันเฉพาะ SQL ที่ `/admin/system` ระบุ ห้ามรัน Seed หรือ Bootstrap ซ้ำเพียงเพราะการเชื่อมต่อล้มเหลว
- หลังเผยแพร่ให้รอ Live Update ชั่วครู่ ถ้ายังเห็นข้อมูลเก่าให้กด `Ctrl+F5`; มือถือปิดแท็บเดิมแล้วเปิด URL ใหม่เพื่อรับ Service Worker ล่าสุด
- ปุ่ม Info ขึ้นแต่ Dialog ไม่มีข้อมูล ให้ตรวจ Scene ID/Hotspot ID, สถานะเนื้อหา Published และสถานะเผยแพร่โครงสร้างตามลำดับ
